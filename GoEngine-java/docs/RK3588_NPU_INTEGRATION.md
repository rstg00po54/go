# RK3588 RKNPU2 integration (9x9 / 13x13 / 19x19)

This branch is derived from `rk3588-engine` and does **not** replace it.
The existing `eigenjni` and `opencljni` builds remain unchanged.
The native backend accelerates the original
`g170-b10c128-s1141046784-d204142634` KataGo 10b NN with one fixed-shape
RKNPU2 model per supported board size: 9x9, 13x13, and 19x19.

The 19x19 model is the version previously tested on RK3588. New 9x9 and
13x13 models were independently generated by GitHub Actions using KataGo
1.18.1 `dumponnx` (same 10b weights), followed by RKNN-Toolkit2 2.3.2.
Both conversions and checksums passed on GitHub Actions, **but the new
models have not yet been run on the user's actual RK3588**. Do not mistake
successful RKNN compilation for correctness or tested speed.

The Human SL `b18c384nbt-humanv0` network **still runs on Eigen CPU** within
the NPU library. The Human SL network needs its own b18 ONNX export, RKNN
compilation, accuracy tests and NN input/head mapping. Selecting NPU in the
app must not be interpreted as an NPU-accelerated Human SL policy.

## Compile on the Ubuntu x86 host

For RK3588 Android 14, Android SDK/NDK, Eigen, CMake and Ninja should already
be installed for `eigenjni`. Use the **same** `rk3588-engine` workspace:

```bash
cd /mnt/hgfs/D/code/go/GoEngine-java
git fetch
git switch feature/rk3588-rknn
bash tools/prepare_rknn.sh --multisize
KATAGO_JOBS=2 bash tools/build_katago_from_source.sh rknnjni
# Check the RK3588 target first. Only use this path if device page size = 4096.
adb -s 8719e18a71a2a66c shell getconf PAGESIZE
ALLOW_4K_RKNN_RUNTIME=1 bash build.sh --apk-only
```

`prepare_rknn.sh` reuses cached MiniGoCpp artifacts when available; else
downloads the 19x19 model from its release plus Rockchip's Android
`librknnrt.so` and `rknn_api.h` **v2.3.2** into ignored working paths.
With `--multisize`, it also downloads and SHA-256-verifies 9x9 and 13x13
from [MiniGoCpp's multi-size release](https://github.com/rstg00po54/MiniGoCpp/releases/tag/katago-10b-rknn-multisize-v1).
Without the flag the 19x19-only build still works offline.
No binaries are committed to the source tree.

The build should produce:

- `build/katago_android_arm64_rknnjni/libkatago_npu.so`
- `build/rknn_sdk/librknnrt.so`
- `app/src/main/assets/engine/katago_10b_19x19.rknn`
- `app/src/main/assets/engine/katago_10b_9x9.rknn`
- `app/src/main/assets/engine/katago_10b_13x13.rknn`
- `app/build/outputs/apk/debug/app-debug.apk`

Gradle packages the model and runtime only when they are present and
`-PenableKataGoNpuJni=true` (or auto-detection) enables the NPU backend.
Disable experimental packaging with `-PenableKataGoNpuJni=false`.

## Device verification

Install the resulting APK on **RK3588S**, select **9路、13路或19路** and **NPU / RKNN**
in New Game, and play a few moves. Confirm log entries from the native
NN-server thread containing `RKNN (RK3588 NPU)`, plus Java startup messages
identifying the NPU session. The 10b and Human SL b18 should show separate
backend labels.

```bash
adb -s 8719e18a71a2a66c install -r app/build/outputs/apk/debug/app-debug.apk
adb -s 8719e18a71a2a66c logcat -d -v time | grep -E 'RKNN|NPU|Backend requested:|Game backend requested=' | tail -60
```

After confirming GTP startup, compare identical 9x9 / 13x13 / 19x19 positions between
NPU and CPU: candidate moves, ownership and score estimates. The existing
MiniGoCpp test validates all five RKNN heads against an ONNX reference on
an **artificial** 19x19 input, not the App's real board inputs or complete
MCTS search. The 9x9 / 13x13 releases still need an equivalent reference
check on RK3588. Do not call them fully validated until tests pass.

## Technical constraints

- For board size N in {9, 13, 19}, 10b NN tensors are
  `InputSpatial [1,22,N,N]`, `InputGlobal [1,19,1,1]`,
  `InputMask [1,1,N,N]`. The RKNN files are **independently converted**
  (not renamed/cropped from the 19x19 binary).
- Output heads: `OutputPolicyPass`, `OutputPolicy`, `OutputValue`,
  `OutputScoreValue`, `OutputOwnership`.
- RKNN runner uses the NHWC spatial input prepared by KataGo and constructs
  `InputMask` from feature plane 0. It performs FP32 input/output marshaling,
  while the NPU model uses the converter's internal precision.
- A single NPU core (0) and batch=1 are used for the first integration.
- 9x9 and 13x13 use their dedicated NPU graph if the APK contains it;
  11x11 and 15x15 stay on CPU/GPU for now. A missing 9x9/13x13 asset
  never makes the app run the 19x19 graph under the wrong dimensions.
- Failure to initialize RKNN should fall back to Eigen with an explicit log.
- The existing 19x19 NPU backend has been built and used for successful
  GTP play on the user's RK3588. The **new** size-specific code and models
  still require host-side APK compilation and RK3588 accuracy/performance tests.

## Future Human SL acceleration

Convert the actual `b18c384nbt-humanv0` network separately. Capture the
human-rank conditioning inputs and model version, compare all heads against
the native Eigen Human SL output for multiple ranks and legal 19x19 games,
then extend the backend's model dispatch. Conversion success and NPU support
for the full b18 graph remain to be established.

## Important: Rockchip runtime page alignment and phone builds

The RKNPU2 Android runtime `librknnrt.so` from Rockchip v2.3.2 in
`tools/prepare_rknn.sh` has ELF `PT_LOAD p_align=0x1000`. The native
`libkatago_npu.so` and our other JNI libraries are correctly linked with
`p_align=0x4000`.

To avoid weakening checks accidentally, APK packaging will **reject** the
Rockchip runtime by default. For development on RK3588 Android systems verified
to use **4 KB memory pages** (`adb shell getconf PAGESIZE` returns `4096`),
opt in using `ALLOW_4K_RKNN_RUNTIME=1 bash build.sh --apk-only`. Gradle
then validates only the exact `librknnrt.so` by a 4 KB threshold and keeps
the 16 KB requirement for every other packaged ELF. The final APK inspection
explicitly prints a `WARN` and does not count this runtime as 16 KB compatible.

Do **not** ship that APK for a 16 KB page-size device or publish it as an
all-device 16 KB-compatible APK. For such devices, obtain and validate a truly
16 KB-aligned Android `librknnrt.so` from the SoC/firmware vendor, or produce
a separate phone build without the Rockchip NPU backend and its dependencies.
The vivo smartphone uses its CPU/GPU backend, **not** Rockchip's RKNN runtime.

## Automated Android multi-size switching test with GitHub upload

The debug APK exposes a test-only `npu_switch_smoke` intent. It uses the
same `KataGoEngine` in one app process, sequentially opens
**9x9 -> 13x13 -> 19x19 -> 9x9**, and generates one black and one white
move on every board. It checks the exact board-specific model path and
`RKNN_READY` native event, not just whether Java requested "NPU".
Native CPU fallback, wrong old-model reuse, timeout and crash all fail.

After building/installing the multi-size NPU APK on **4 KB page RK3588**:

```bash
git pull --ff-only
ALLOW_4K_RKNN_RUNTIME=1 bash build.sh --apk-only
python3 tools/smoke_android_npu_switch.py --serial 8719e18a71a2a66c
```

The script installs the APK, force-stops the app and clears its device
logcat buffers for this isolated test. **By default it automatically
uploads PASS/FAIL reports and filtered logs to the public GitHub
`ui-test-results` branch** using the working Git credentials configured
on the Ubuntu host. It does not modify the source branch or stage other
working-tree changes. Files stay locally at `build/android_npu_smoke/<UTC run>/`
even if Git credentials or network prevent uploading.

Common switches:

```bash
# Test the already installed APK without installation
python3 tools/smoke_android_npu_switch.py --serial 8719e18a71a2a66c --skip-install
# Isolate NPU 10b without CPU Human SL setup
python3 tools/smoke_android_npu_switch.py --serial 8719e18a71a2a66c --no-human-sl
# Local only; do not publish logs
python3 tools/smoke_android_npu_switch.py --serial 8719e18a71a2a66c --no-upload
# Retry failed upload later, without connecting the Android board
python3 tools/smoke_android_npu_switch.py --upload-existing build/android_npu_smoke/<UTC run>
# Parser and uploader offline regressions
python3 tools/test_smoke_android_npu_switch.py
python3 tools/test_upload_referee_test_results.py
```

**Privacy**: Results branch is public. Uploads contain the test summary
(including ADB serial), filtered KataGo/NPU logcat, platform/page-size
information, and crash diagnostics if present. Use `--no-upload` when
those details should remain local. Git credentials are never embedded in
scripts; if the host cannot push to GitHub the upload is reported as
failed instead of pretending it succeeded.

The GitHub Actions offline Python tests verify log parsing and isolated Git
upload behavior, **not actual NPU inference**. Actual 9/13/19 board hardware
results can be judged only after this script runs against the RK3588.

## Automatically display crash C++ functions and lines

Android's normal `adb logcat -b crash` records program counters and sometimes
exported symbol names, but **cannot normally display source file/line numbers**.
The Ubuntu host has the matching DWARF-enabled ELF and can resolve exact source
lines without modifying Android's system crash handler or the APK.

To watch **future** crashes while using the board, in a separate Ubuntu terminal:

```bash
python3 tools/watch_npu_crash.py --serial 8719e18a71a2a66c
```

On every new `libkatago_npu.so` crash it prints lines like:

```text
#00 0x00000000000dc798 ScoreValue::expectedWhiteScoreValue(...) @ native/KataGo/cpp/neuralnet/nninputs.cpp:214
#01 0x000000000013c194 Search::getScoreUtility(...) @ native/KataGo/cpp/search/searchhelpers.cpp:276
```

It stores `crash.txt` and `native_symbols.txt` together under
`build/npu_crashes/<timestamp>_pid<id>/`. It does not erase logcat or change
Android process behavior. To decode the most recent **existing** buffered
crash and exit:

```bash
python3 tools/watch_npu_crash.py --serial 8719e18a71a2a66c --include-existing --once
```

The existing real-game test `bash tools/test_rk3588_npu_game.sh` now also
starts the watcher automatically, and its failure diagnostics prints the
symbolized frames and includes them in the GitHub results upload.
`NPU_CRASH_WATCH=0` disables just the live watcher when necessary.

The exact Build ID of the crash frame **must match** the local ELF produced by
`tools/build_katago_from_source.sh rknnjni`; if it does not, the symbolizer
rejects it instead of misleadingly reporting unrelated source lines.
Override the source ELF path with `KATAGO_NPU_ELF=/path/to/libkatago_npu.so`.
The ELF must contain DWARF; `??:0` indicates missing debug information.

## Experimental original Human SL b18 RKNN on RK3588 (9x9, October 2026)

The original `b18c384nbt-humanv0.bin` (107185997 bytes) is exported with
KataGo 1.18.1 `dumponnx`, then 120 mathematically equivalent Mish chains are
rewritten without changing any of the original 504 initializer tensors.
All five ONNX output heads passed four CPU parity cases across varying Human
metadata vectors. The RKNN-Toolkit2 2.3.2 float16-weight/float32-I/O build
now **compiles successfully** on GitHub Actions for **9x9**. The first
successful build SHA-256 was
`3692a0726ae4e0f5fd601cdc782cb04fe60e6a0c6f06c2789f6e073d52f61474`.
Repeat RKNN compilation can produce a different binary digest; each released
model is therefore verified against its own compiler-generated JSON manifest.

- Successful [CI run](https://github.com/rstg00po54/go/actions/runs/38839604816)
  contains the RKNN artifact, manifest and conversion reports.
- Experimental [public release](https://github.com/rstg00po54/go/releases/tag/rk3588-human-b18-9x9-experimental-v1)
  is published by a separate successful workflow run (when available).
- These files are **not yet verified on the physical RK3588**; the working
  10b JNI backend continues unchanged and Human SL in the app still uses CPU.
- 11x11, 13x13, 15x15 and 19x19 original Human b18 RKNN are not built yet.

Board-only probe (does **not** reinstall or modify the existing Android APK):

```bash
cd /mnt/hgfs/D/code/go/GoEngine-java
git pull --ff-only
bash tools/test_rk3588_human_rknn.sh 8719e18a71a2a66c
```

The script verifies the compiled model's SHA-256, stages Rockchip's Android
`librknnrt.so` and an NDK-built tiny probe under `/data/local/tmp`, tests the
four RKNN inputs and five heads with two synthetic metadata conditions,
checks numeric finiteness, and writes `build/rk3588_human/device_probe/device_smoke.log`.
If the release is not online yet, it can fetch the successful workflow
artifact with authenticated `gh` CLI instead. `HUMAN_RKNN_MODEL` allows
specifying an already downloaded `.rknn` file.

**Important**: Probe `HUMAN_RKNN_SMOKE_PASS` means load and synthetic inference
only. It does not validate original KataGo rank metadata encoding, CPU/NPU
five-head numerical parity, policy/ownership channel ordering, search behavior,
or playing strength. The full Android C++ Human backend must not be enabled
until those checks have been completed. The exported b18 graph uses
`scale8Applied=true` and a postprocessing multiplier of 8; that contract
must be accounted for when integrating the network into KataGo.

## 原始 Human SL b18：CPU / RK3588 NPU 五输出精度验证（9×9）

已新增独立的对照测试，不修改现有围棋 APK 或 10b NPU 后端。
GitHub Actions 使用原始 `b18c384nbt-humanv0.bin` 导出的 ONNX，
由 ONNX Runtime CPU 产生 4 组固定测试数据，并把四个输入张量和五个输出头
打包为 `human_b18_cpu9_reference.bin`。

```bash
cd /mnt/hgfs/D/code/go/GoEngine-java
git pull --ff-only
bash tools/test_rk3588_human_parity.sh 8719e18a71a2a66c
```

脚本会验证参考数据 SHA-256、编译 Android ARM64 对照程序、通过 ADB
上传独立测试程序和参考数据，再调用 RK3588 实际 NPU 进行逐元素对比。
输出包含每个输出头的 `maxAbs`、`meanAbs`、`outOfTolerance` 和最终
`HUMAN_CPU_NPU_PARITY PASS/FAIL`。首次误差阈值为
`abs_error <= 0.05 + 0.03 * abs(cpu_value)`，如失败必须核对数据布局、
转换图和 FP16 精度，不能直接提高阈值来宣称通过。

**验证边界**：这四组仍是确定性的合成输入；即便通过，也不能证明
原生 KataGo Human SL 棋力编码正确、真实棋局精度或 Android 正式接入完成。
下一阶段再使用 KataGo C++ 实际生成的棋局特征和人类等级元数据交叉验证。

### 自动上传精度对比结果

## RK3588 Human SL b18 原生 Android 实际对弈实验（严格手动启用）

原始 b18 的 RKNN 9×9 模型已经通过四组合成输入的 RK3588 CPU/NPU 对照。
接下来，KataGo 的 RKNN JNI 内增加独立的 `KataGoHumanRknnRunner`。
此接口不改变原先 10b 的推理路径，也不修改 KataGo 的原始人类棋力编码；
`SGFMetadata::fillMetadataRow` 继续生成包含段级、双方身份、棋局时间等内容的 192 维输入。
原始 Human 9×9 NPU 输出的两条 policy 通道从 NCHW 转为 KataGo Eigen 所需的 NHWC。

**安全约束**：只有在应用私有目录 `files/engine` 内同时存在
`katago_human_9x9.rknn` 和 `enable_human_rknn_9x9.flag`，
并且已经选择 9×9 NPU 与 Human SL 时，才开启实验模型。否则仍走 CPU Human。
可以开启 `KATAGO_RKNN_HUMAN_COMPARE_CPU=1`，使用相同真实棋局的四组
Human 前向计算结果与原生 Eigen 对比，各五个输出头逐一报告误差；
超出容差会禁用这次 Human NPU 并回退 CPU。

一键实机流程（从源码同步开始）：

```bash
cd /mnt/hgfs/D/code/go/GoEngine-java
git pull --ff-only
bash tools/test_rk3588_human_game.sh 8719e18a71a2a66c
```

这条命令会重编 RKNN JNI 和 APK、安装调试 APK、复用已下载的 9×9 Human RKNN、
把模型复制进应用私有目录，临时开启实验标记，运行现有 9×9 NPU / Human SL
真实 GTP 自动测试，验证 Human NPU 初始化、5 输出头原生 CPU 对照与无回退，
并将成功/失败报告上传到公共 `ui-test-results` 分支。
**结束时自动删除开启标记**（模型文件缓存保留），下次普通启动默认仍使用 CPU Human。

可用 `HUMAN_RKNN_SKIP_BUILD=1` 跳过编译，但前提是设备上调试 APK
已包含本次 C++/JNI/Java 修改。可额外加 `--no-upload` 禁止公开上传日志。
实机测试结果以 GitHub 上传报告为准；云端编译通过不等于本步骤通过。

### 首次真实局面测试失败及 scale8 修复（2026-10-16）

首次真实 9×9 Human b18 NPU 测试已自动上传到 `ui-test-results` 分支，
报告 `runs/20261016T032146288480Z_npu_763363_086e3be5.json` 为 `FAIL`。
10b NPU、Human b18 四输入五输出、原生 `rank_12k` 都正常，
但五输出头相对 Eigen CPU 的原始值偏差很大，安全回退 Human CPU。

原因：KataGo 1.18.x 的 `dumponnx` 默认启用 `scale8Applied=true`，
导出的 ONNX 图将激活缩小八倍以避免 FP16 范围溢出，元数据中
`katago.postProcess.outputScaleMultiplier=8`。独立 ONNX vs RKNN 对比
均使用相同的 1/8 单位，因此先前可以 20/20 全部通过；
而 Eigen 原生 `.bin` 推理返回未经缩放的原始输出。
首次 Android Human RKNN 适配器遗漏了全五输出头 `×8` 还原。

`humanrknnbackend.cpp` 现已在 NCHW→NHWC 处理之前对五头统一乘以 8，
并在 `HUMAN_RKNN_READY` 日志显示 `scale8Compensation=8`。
原生五头对比日志现在额外显示最差数据位置的 `cpu` 与 `npu`，
严格测试脚本还会拒绝缺少缩放标记的旧 APK。
**该修复仍须重新运行实机验证，不可在新测试结果出现前宣称 PASS。**

```bash
git pull --ff-only
bash tools/test_rk3588_human_game.sh 8719e18a71a2a66c
```
