# KataGo PASS 搜索访问次数实测（2026-10-14）

- [GitHub Actions 实测日志](https://github.com/rstg00po54/go/actions/runs/38500176798)
- 实测引擎：KataGo v1.15.0、v1.18.1，均在 Linux x86_64 CPU/Eigen AVX2，使用仓库 `10b.bin` 模型。
- 19 个仓库局面：9 个复杂静态棋形、3 个基础静态棋形、6 盘真实已完局棋谱、1 个真实第 64 手快照。
- 每版本、每局面、每档访问次数独立启动 KataGo，每档重复 2 次，合计 228 次；避免不同访问次数交叉复用搜索树。
- 每次执行黑正常、黑强制 PASS、白正常、白强制 PASS 四个原生 GTP 搜索，maxTime=0.5；时间只包括四次搜索，不含 SGF 加载与引擎启动。
- 状态按 Android 阈值大致映射：`PLAY` ≥1.5 目、`SMALL` >0.5 目、`REVIEW` ownershipStdev >0.25、`ALMOST` 否则；实际 APK 还额外检查单气和劫禁。
- **状态一致不代表标记位置一致，更不代表算法已验证能准确裁判死活。测试平台和 RK3588 不同。**

## 值得注意的边界案例

- v1.18.1 的真实棋谱 `cgos9_2`：24 次两遍均为 `ALMOST`，12 次一遍为 `SMALL`，白/黑方预计收益极值约 0.546 目，刚超过显示阈值 0.5。
- v1.15.0 本轮在 19 个局面上没有出现类别差异，但没有直接包含 RK3588 截图第 36 手的 1.438 目、第 46 手的 1.450 目这两盘实际对局，**不能据此保证临界局面正确**。
- 访问次数改变后，搜索推荐着法经常变化。要保持裁判稳妥，建议先试 12 次预判、争议时回退 24 次，再在 RK3588 量实际耗时。
- 仓库合成棋形没有人工独立认证的死活标准答案；本次仅检查 KataGo PASS 分类一致性和性能。
