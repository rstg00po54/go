# KataGo 原生 endGameIfAllPassAlive 终局证明实测

**测试日期：2026-10-14**

- 引擎：KataGo v1.15.0 官方 C++ 原版。运行平台：GitHub Actions Ubuntu 24.04，Linux x86_64 CPU/Eigen AVX2。不是 RK3588/Android 本机。 
- [GitHub Actions 全通过记录](https://github.com/rstg00po54/go/actions/runs/38501379863)。
- 临时将测试用 GTP 命令 kata-test-all-pass-alive 注入 GitHub Linux runner 上的上游源码编译副本；内部直接调用 BoardHistory::endGameIfAllPassAlive(board)。**APK 和正式引擎未修改**。
- 每次以所加载 SGF 的盘面新建未结束的 BoardHistory（避免已双 PASS 的对局历史产生假阳性），只读检测，不落子、不 PASS。
- 共 19 个现有仓库局面：9 复杂合成棋形、3 基础合成棋形、6 完局 SGF、1 真实第 64 手劫局面；另外有两个对照。
- 每盘 3 次重复，每次 C++ 内循环调用原生函数 2000 次。表内耗时为 3 次批量均值的中位数，µs 是**单次 C++ 函数耗时**；GTP ms 是同一条命令执行 2000 次函数的总往返时间。
- 先前 NN 估分列沿用仓库 2026-10-13 已保存的 v1.15.0 实测，不是本次重跑。

## 结论

**19/19 既有局面均不能凭严格 pass-alive 全盘证明结束；两项正负对照均成功。**

- 正对照：双方拥有确定的两只真眼，棋盘所有交叉点都被 Benson 证明确切归属，返回结束，比分 B+34.0。
- 负对照：9 路空棋盘返回未结束。
- 注意这是 **充分条件，不是必要条件**：即使真实棋谱已结束并有赛果，也常常含中立点/死棋等无法由此证明的区域。不能以 false 判定“必须继续下棋”。

## 用于智能裁判时的含义

1. 可以作为**极速的肯定性终局证据**：返回 true 时，全盘属于原生算法可以证明的活棋/地盘布局；它不验证对局双方是否已同意终局。
2. **不能用 false 一票否决终局**：这批仓库样本中即使完成 SGF 也没有通过严格全盘证明条件。它不能取代 KataGo NN、官子检查或中国规则数子。
3. 不依赖 NN 的原生函数本体仅需微秒级，但若在 Android 中为此另启动整个 KataGo 进程，仍有较大的引擎启动开销；应在已有本地 C++/JNI 引擎上直接调用。
4. 仓库静态合成棋形不能用于准确率认证；正负对照验证了该接口在测试编译环境下确实存在真假两种返回。
